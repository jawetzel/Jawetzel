> **What this is.** The strategy doc for turning jawetzel.com from a credibility site
> into a sales-generation tool. It captures **the offer** (who it's for, the result,
> the mechanism, the risk reversal, the reason to act) before any page gets built.
> This is a living canvas — we fill it as we talk through the pitch. Nothing here is

## 1. The raw pitch (Josh's words)

> _Captured verbatim, part by part, as pitched. Decomposition happens in §2 — this
> stays raw._

### Part 1 — main unit of work

- **Fractional Engineer**
- **10h block** addressing unique / specific issues
- **$1500**

### Part 2 — Review (three concepts, $500 each)

Each review is **scope-limited to systematic problems at the page-type / template
level — not a 1500-page scan.** Fix the template, fix it everywhere.

- **Security Review** — *"Am I safe? Am I leaking information I shouldn't be?"*
  - Keys · Configs · Customer info · Admin panels · Proprietary information
- **SEO Review** — *"Am I seen? Do I look quality? Do search engines / AI engines trust me?"*
  - HTML structure · Meta tags · Keyword search · Content swap suggestions · Competitors · Queries worth matching to
- **Accessibility Review** — *"Are my customers having a hard time operating my website? Am I about to get sued?"*
  - HTML structure · Accessibility features · Accessibility issues · Readability · Specific-disability flagging

**Price:** $500 (each).

### Part 3 — Process automation / AI Integration

Discovery hook: **"What do I have to do 40× a day?"**

**Not a separate price tier.** This is an *example of work a block is made of* — a named,
marketable use-case that makes the abstract block concrete. The block is the vehicle;
automation is one thing you drive it to.

Candidate 40×/day work-types (pick 2–3 as the page examples):
retype-from-document · rekey-between-systems · triage-and-route-inbound ·
flag-the-wrong-record · generate-the-document · batch-repair-data.

Differentiator = the wrapper, not the AI: *"dry-run + review so an agent can't quietly
break production."* ROI close: *"a 2-min task done 40×/day ≈ 7 hrs/week — one block buys
it back forever."*

### Part 4 — Legacy Modernization

The pain (Josh's words): **"Old slow app, no longer supported, and not easily extended,
with expensive hosting."** Four distinct hooks: *old/slow · unsupported · can't-extend ·
costly-to-host.*

**Also a work-category, not a tier — but the flagship one.** Delivered as a *sequence of
blocks*: one slice modernized per block, no big-bang cutover, stop after any block. This
is where Josh's proof is strongest (Lipsey's VB→.NET, Fastlane).

## 3. Structure — two SKUs and a funnel

The offer is **not** a five-item menu. It's **two things a buyer can pay for**, plus a
set of **work-categories** that market what the block does.

### Price tiers (what a buyer buys)

- **Review — $500.** Front-end tripwire. **One "Review" product, pick-a-lens** (Josh's
  call): Security / SEO / Accessibility / **Legacy Assessment** (4th lens, modernization's
  front-end). Template-scoped, produces a written report. Single offer + page.
- **Block — $1500 / 10h.** The core unit of work ("Fractional Engineer"). Flexible
  capability, spent on unique/specific issues.

### The funnel

`Review ($500) → finds the problems → Block ($1500) fixes them.`
**Confirmed:** the $500 review **credits into** the block (tripwire-credit).

### Work-categories (marketing surface for the block — NOT tiers)

How you make the abstract block concrete. Each is a headline example / potential SEO
landing page that funnels into "buy a block":

- **Legacy modernization** — the flagship (Part 4). Old/slow/unsupported/costly app →
  modern, supported, extensible, cheaper-to-host. Delivered incrementally, block by block.
- **Process automation / AI integration** — the "40×/day" tasks (Part 3).
- _Others tbd — fix-what-the-review-found, integrations…_

### Continuity (above the block)

- **One-off, buy-as-needed (Josh's call).** No retainer, no standing block. Repeat
  purchase happens *naturally* (a happy buyer comes back for the next block) but nothing
  is committed. Pairs cleanly with cost-of-waiting: *problem now → block now → fixed.*
  Lowest-friction ask.

## 4. Open decisions

**The three closing blanks — RESOLVED:**
1. ~~Who it's for~~ → **Broad**, specificity pushed to work-category pages.
2. ~~Reason to act now~~ → **Cost of waiting** (review fear-hooks = the engine).
3. ~~Continuity~~ → **One-off, buy-as-needed.**

**Mechanics — RESOLVED:**
- ~~Reviews packaging~~ → **one "Review" product, pick-a-lens** (4 lenses inc. Legacy Assessment).
- ~~Review credits into block~~ → **yes.**
- ~~4th "Legacy Assessment" review~~ → **yes** (as the 4th lens).

**Still open:**
- **Self-serve vs. inquire-first.** Both SKUs are now fixed-price one-offs → a Stripe
  "buy a block" / "buy a review" button is on the table (Stripe already demoed on-site).
  Big friction cut, but changes every page's CTA from "book a consult" to "buy now."
- **Retire the capacity-scarcity badge** on the live homepage / BR page (contradicts the
  one-off + cost-of-waiting decisions above).
